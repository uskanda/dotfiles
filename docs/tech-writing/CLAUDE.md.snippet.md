# CLAUDE.md への追記案

`~/.claude/CLAUDE.md` の末尾に、下の囲みの中身をそのまま追記する。
skill が発火しない場面（コーディング中のコメント記述など）でも効かせるための最小規約である。

分量は30行以内に抑えてある。増やすと常時の context 消費が増え、他の指示との競合も起きる。
詳細を足したくなったら CLAUDE.md ではなく skill `tech-writing-ja` 側に足す。

---

```markdown
## 日本語技術文書の規約

詳細は skill `tech-writing-ja` にある。以下は常時適用する最小規約。

- 文体は文書内で統一する。既定は常体（である調）。手順書と README は敬体でもよい。
- 一文は90字以内、読点は3つまで。一文一義。段落の先頭に結論を置く。
- 次を書かない: 「〜することができる」「〜を行う」「〜となっている」「〜な形で」
  「〜と思われる」「〜と考えられる」「まず初めに」「〜する必要がある」。
- 見出しの言い換えを直後の文に書かない。同じ事実を文書内で2回書かない。
- 根拠のない三つ組（「保守性・可読性・拡張性が向上する」）を書かない。
- 「簡単に」「単に」「もちろん」を書かない。絵文字と感嘆符を使わない。
- 読者への呼びかけ（「〜しましょう」）を書かない。手順は命令形で書く。
- 500字を超える文書は、冒頭に「対象読者」と「前提知識」を1〜3行で書く。
  そこに無い専門用語は、初出時に言い換えるか括弧で定義する。
- 略語は初出で「正式名称（略語）」と書く。1つの概念には1つの語を使う。
- 「上記」「下記」ではなく見出し名で参照する。「現在」「最新」ではなく版と日付で書く。
- 事実は断定する。未確認なら「未確認」と書き、確認方法を添える。
- コメントは**なぜ**を書く。何をしているかはコードで表す。
  コードを読めば分かることと、コメントアウトしたコードを残さない。
- TODO には追跡先（issue 番号か担当）を必ず書く。
- 出力する前に、意味を変えずに20%短くできないか試す。
```

## 反映手順

このリポジトリの `~/.claude` は allowlist 方針で管理している（README 参照）。
実ファイルを編集してから chezmoi に取り込む。

```bash
# 1. 実ファイルを編集する
$EDITOR ~/.claude/CLAUDE.md

# 2. chezmoi のソースへ取り込む
chezmoi add ~/.claude/CLAUDE.md

# 3. 差分を確認してからコミットする
chezmoi diff
```

## 外すときの目安

段階3の測定（[`proposal.md`](proposal.md) §8）で、次のどちらかが分かったら CLAUDE.md 側から外す。

- skill が期待どおり発火しており、CLAUDE.md の記述が重複している
- 特定の項目が守られていない。その項目は表現を変えるか skill 側へ移す
